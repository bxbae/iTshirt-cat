# 캣북스 — 책·문구 온라인 서점 + 영수증 기반 고객지원 (데모)

책·문구·굿즈를 사고, 후기를 남기고, 문의·환불을 신청하는 **서점 사이트**와, 그 뒤에서 **환불·보상을 규정과 영수증으로 판정**하고 상담원의 답변을 돕는 **고객지원 콘솔**입니다.
[`bxbae/cs-bridge`](https://github.com/bxbae/cs-bridge)의 상담 코파일럿(개인정보 마스킹 · 정책 검색 · 답변 초안 · 검증 가드)을 한국어 서점 정책으로 옮기고, 그 위에 쇼핑몰과 클레임 자동 판정, 반품 입고 순 보상 큐를 새로 만들었습니다.

> 교보문고 사이트의 구성(상단 검색·카테고리 메뉴, 상품 상세의 구매 영역, 구매 후기, 주문·배송 조회)을 참고한 **독자 구현**입니다. 로고·이미지·문구·상품 데이터는 쓰지 않았고, 상품·저자·출판사는 모두 가상입니다. 결제와 배송은 실제로 일어나지 않습니다.

## 실행

가장 빠른 방법 (Python 3.11+ 와 Node.js 20+ 필요, 처음엔 패키지 설치로 1~2분):

```bash
git clone https://github.com/bxbae/iTshirt-cat && cd iTshirt-cat
git checkout claude/inspiring-newton-m40h9p
./start.sh        # (Windows: powershell -ExecutionPolicy Bypass -File .\start.ps1  또는 start.bat 더블클릭)
                  # 쇼핑몰 http://localhost:3000 · 상담원 http://localhost:3000/admin
```

따로 실행하려면:

```bash
# 1) 백엔드 (API 키 없이 mock 모드로 바로 실행, 첫 실행 때 데모 데이터 생성)
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 2) 프런트엔드
cd frontend
npm install
npm run dev            # http://localhost:3000
```

Docker: `cp .env.example .env && docker compose up --build`
실제 LLM으로 답변 초안 만들기: `LLM_PROVIDER=anthropic ANTHROPIC_API_KEY=sk-ant-...` (환불 판정은 LLM과 무관하게 규칙 엔진이 합니다)

| 주소 | 내용 |
|---|---|
| `/` `/products` `/products/:id` | 홈, 목록(카테고리·검색·정렬), 상품 상세와 구매 후기 |
| `/cart` `/checkout` | 장바구니, 결제(적립금 사용) |
| `/orders` `/orders/:id` | 주문·배송, 영수증, 취소·반품·교환·보상 신청, 후기 쓰기 |
| `/support` | 자주 묻는 질문, 1:1 문의와 답변 |
| `/admin` | 상담원 대시보드 |
| `/admin/console` | 상담 콘솔(문의함 · 대화 · 코파일럿) |
| `/admin/claims` | 클레임 판정 근거, 승인·거절, 처리 기록 |
| `/admin/queue` | 보상 큐(입고 순서) |
| `/admin/reviews` `/admin/kb` | 후기 관리, 정책 지식베이스 |

로그인은 데모용입니다. `/login`에서 가상 고객 5명 중 한 명을 고르면 됩니다.

## 핵심 1 — 영수증·규정을 벗어난 신청을 자동으로 처리

`backend/app/rules/refund.py`의 `decide()`는 같은 입력이면 항상 같은 결과를 내는 순수 함수입니다. 결과는 5가지입니다.

| 결과 | 의미 |
|---|---|
| 자동 승인·지급 | 출고 전 취소, 배송 지연 보상처럼 바로 지급 |
| 승인(입고 후 지급) | 반품·교환. 상품이 입고·검수되면 보상 큐에서 지급 |
| 자료 요청 | 불량·파손·오배송인데 사진이 없음. 사진을 추가하면 자동으로 이어서 판정 |
| 상담원 확인 | 한도 초과, 영수증 금액 초과, 전자책 오류, 미수령, 점검 대상, 검수 불일치 |
| 자동 거절 | 규정·영수증 위반. 사유와 규정 번호(예: `KB-REF-01#1`)를 함께 안내 |

**영수증과 맞대어 보는 항목**: 주문자, 영수증에 있는 상품인지, 남은 수량(이미 환불됐거나 처리 중인 수량 제외), 결제 금액과 적립금 사용분, 배송비, 배송 예정일과 실제 도착일.
**벗어난 경우의 처리**: 수량이 많으면 영수증 기준으로 **보정**, 규정보다 많은 금액을 요구하면 규정 금액으로 **보정**, 영수증 금액 자체를 넘으면 **상담원 확인**, 영수증에 없는 상품은 **거절**합니다.

| 규정 | 값 |
|---|---|
| 단순변심 | 수령 후 7일, 미개봉·미사용, 반품 배송비 3,000원 차감 |
| 불량·파손·오배송 | 수령 후 30일, 사진 필요, 배송비 무료, 입고·검수 통과 시 보상 적립금 2,000원 |
| 환불 불가 | 전자책, 주문제작 굿즈, 개봉·사용한 상품(단순변심) |
| 배송비 | 15,000원 이상 무료, 일부 반품으로 기준 미달 시 2,500원 차감 |
| 배송 지연 보상 | 예정일보다 3일 늦으면 1,000원, 7일 늦으면 3,000원(적립금, 주문당 1회) |
| 자동 처리 한도 | 환불·보상 합계 100,000원 초과는 상담원 승인 |

숫자는 `rules/policy.py`에 있고, 같은 숫자가 고객에게 보이는 정책 문서(`app/kb`)에도 있습니다. 테스트가 둘이 일치하는지 확인합니다.
고객은 신청하기 전에 **같은 규칙으로 계산한 예상 결과**(환불액, 차감 내역, 거절 사유)를 미리 볼 수 있습니다.

**"학습"에 대해**: 현재는 기계학습이 아니라 **규칙 + 판단 이력 수집**입니다. 상담원이 규칙 판정을 승인·거절하면 (규칙이 낸 결과, 상담원 결정, 걸린 규칙)이 감사 기록에 쌓이고, `/admin/claims`와 대시보드가 "규칙 판정을 뒤집은 건수"를 보여 줍니다. 이 기록이 규칙과 임계값을 고칠 근거입니다. 반복 신청 이력에서 나오는 내부 점검 점수(60점 이상이면 자동 승인 안 함)는 **고객에게 보이지 않고** 답변 초안에도 들어가지 못하게 막혀 있습니다.

## 핵심 2 — 반품 입고 순서로 보상을 처리하는 큐

`backend/app/queue.py`. 반품 상품이 물류센터에 **입고된 시각**이 줄 순서입니다(신청한 시각이 아님). 다음 조건을 모두 만족하면 순서대로 환불·보상을 지급합니다.

1. 입고 검수가 정상(신청 사유와 상품 상태가 일치)
2. 상담원 보류 없음 — 점검 대상이면 상담원 승인 필요
3. 처리 금액이 자동 처리 한도 이내 — 넘으면 상담원 승인 필요
4. 교환이면 교환 상품 재고가 있음 — **재고는 먼저 입고된 건에 먼저 배정**

조건이 안 맞는 건은 사유를 달고 줄에 남고, 뒤의 건을 막지 않습니다. 미리보기(`GET /api/admin/queue`)와 실제 처리(`POST /api/admin/queue/process`)는 같은 순서·같은 재고 계산을 씁니다. "최대 N건만 처리"도 가능합니다.

## 추가로 넣은 기능

- 신청 전 환불액 미리보기 (고객), 사진 추가로 자동 재판정, 신청 철회
- 모든 판정과 지급의 감사 기록, 규칙 번호 인용
- 답변 초안 가드: 근거 없는 금액 약속, 거절된 신청(주문에 여러 신청이 있어도 항목·금액·번호로 식별)에 대한 환불 약속, 확인 전 결과 약속, 내부 점검 정보 노출, 후기 삭제 조건 보상 제안, 개인정보, 단정적 표현을 보내기 전에 막음(서버에서도 422)
- 문의에 주문을 연결하면 영수증과 클레임 판정을 근거로 초안을 작성, 고객이 언급한 상품의 신청을 골라 답변
- 후기: 구매 인증, 상품당 1회, 개인정보·링크·비속어·광고성 자동 보류와 상담원 승인, 낮은 별점+불량·배송 언급은 선제 연락 대상으로 표시
- 보상은 적립금으로 지급되고 장부(`point_ledger`)에 남음, 결제 시 적립금 사용·환불 시 반환
- 대시보드: 문의·클레임 추이, 자동 처리율, 자주 걸리는 규칙, 큐 앞줄, 가드 적발

## 데모 시나리오

| 고객 | 볼 수 있는 것 |
|---|---|
| 김민지 | 새 주문·취소, 배송 지연 보상(주문 상세의 데모 도구로 배송을 진행), 단순변심 반품 |
| 박서준 | 반품 입고 대기 · 입고 완료 건, 지연 보상 자동 지급 |
| 이하은 | 기간 경과 자동 거절, 검수 불일치 보류, 영수증 금액 초과 신청 |
| 정도윤 | 반복 신청 이력 → 상담원 확인 |
| 최유나 | 주문제작 머그컵 반품 거절 + 같은 주문의 교환 건, 교환 재고 경쟁, 미수령 신청 |

관리자 화면에서 `/admin/queue`의 입고 처리 버튼으로 줄을 만들고 "순서대로 처리"를 눌러 보세요.

## 구조

```
backend/app
├── rules/refund.py      클레임 판정 (순수 함수)        rules/abuse.py  반복 신청 신호(내부용)
├── rules/policy.py      정책 숫자와 규칙→KB 번호 매핑
├── claims.py            신청 → 판정 → 지급 워크플로, 감사 기록
├── queue.py             입고 순 보상 큐
├── shop.py              가격·재고·적립금 계산, 후기 스크리닝
├── cs.py                문의 워크플로 (초안 생성, 가드, KPI)
├── copilot/             cs-bridge에서 옮긴 부분: pii · retrieve(한국어 BM25) · validate(가드) · llm(mock/Claude)
├── kb/                  한국어 정책 문서 7개
├── api_shop.py          고객용 API        api_admin.py  상담원용 API
└── seed.py              데모 데이터 (실제 서비스 로직을 과거 시각으로 실행해 생성)
frontend/                Next.js 14 + Tailwind (쇼핑몰은 초록, 콘솔은 인디고 테마)
e2e/browser-flow.mjs     브라우저 시나리오 (Playwright)
```

## 테스트

```bash
cd backend && pytest -q          # 70개: 판정 규칙, 큐 순서·재고, API 흐름, 가드, 정책 문서-규칙 일치
cd frontend && npx tsc --noEmit && npm run build

```

## 한계 (먼저 알아 두세요)

- **인증이 없습니다.** 고객은 `X-User-Id` 헤더, 상담원 API(`/api/admin`)는 열려 있습니다. 데모 전용이며 실제 서비스 전에는 로그인·권한이 필요합니다.
- Claude 답변 생성(`LLM_PROVIDER=anthropic`)은 요청 형식 테스트만 했고 **실제 API로는 실행해 보지 않았습니다.** 기본 mock은 영수증 사실과 정책 문장을 조합합니다. 판정은 어느 쪽이든 규칙 엔진입니다.
- 결제·배송·사진 업로드는 모의입니다(사진은 첨부 개수만 반영). 정책 수치는 이 데모를 위해 정한 값이며 실제 법률 검토를 거치지 않았습니다.
- 한국어 검색은 BM25 + 조사 제거·글자 쌍 방식이라 서점 정책 수준의 소규모 문서에 맞춰져 있습니다. 문서가 커지면 임베딩 검색으로 바꾸세요(`Retriever` 인터페이스 분리됨).
