- 수유·성장 기록: 베이비타임(터치 한 번 기록, 공동 양육자 실시간 연동), 베이비 트래커(통계 그래프, 좌/우 모유 타이머)
- 병원·건강: 똑닥(실시간 대기, 접수·예약, 영유아 검진·예방접종), 열나요(체온·체중별 해열제 용량·간격, 교차 복용 알람)

### 우리 기획에 주는 시사점
1. **직접 경쟁은 적다**: 위 앱들은 기록·병원·건강·커머스 중심이고 동화·동요 콘텐츠 앱이 아니다. 동화·동요 경쟁은 핑크퐁, 베이비버스, 유튜브 키즈 등 별도로 조사해야 한다.
2. **이유식 기록은 겹친다**: 베이비타임이 이유식 기록을 이미 제공한다. '새 재료 기록'(기획서 p.4)이 기존 앱과 무엇이 다른지(알레르기 반응, 도입 재료 기준 추천 등) 인터뷰·설문에서 확인해야 한다.
3. **수익 모델 참고**: 기존 앱은 광고·커머스·제휴·구독으로 수익을 낸다. 우리는 '광고 없는 무료'를 내세우므로 수익 구조 질문(설문 F, 인터뷰 Q28)이 더 중요해진다. 커머스 연계도 검토할 수 있다.
4. **AI 트렌드의 양면성**: 시장은 AI 상담·분석을 환영하는 방향이지만, 건강 정보는 오류 시 위험하다. 이유식 면책 문구와 소아과 상담 안내(기획서 p.4, p.8)를 유지해야 한다. 아이 콘텐츠의 AI 수용도는 위 트렌드와 별개로 직접 검증이 필요하다.
5. **병원·건강 앱과의 제휴 가능성**: 똑닥, 열나요 이용 부모가 타깃과 겹치므로 후속 인터뷰 모집 채널로도 쓸 수 있다.

### 시사점
1. **'무료 + 광고 없음'은 단독 차별점이 약할 수 있다.** 핑크퐁은 멤버십으로 광고를 차단하고, 유튜브 키즈는 보호자 설정을 이미 갖췄다. 설문에서 갈아탈 이유가 실제로 되는지 확인해야 한다(설문 B6, C2, F1).
2. **잠자리 모드 유사 기능이 이미 있다.** 동화 앱 중 자장가 모드를 내세운 앱이 있고 유튜브 키즈에도 타이머가 있다. 인터뷰 Q21에서 기존 방식과 비교해 물어볼 것.
3. **통합 앱 선례는 코코지다.** 여러 IP를 모은 오디오 앱이므로, 사용 경험자를 인터뷰하면 통합 앱에 대한 반응을 알 수 있다.
4. **가장 큰 격차는 캐릭터 IP 인지도다.** 기획서의 자체 캐릭터 IP 전략(p.2)이 부모에게 설득력이 있는지 설문에서 물어볼 필요가 있다.
5. **이유식을 함께 제공하는 앱은 이번 조사에서 확인되지 않았다.** 다만 검색 범위가 좁아 '없다'고 단정할 수는 없다. 이유식+콘텐츠 통합이 빈틈인지 별도 확인이 필요하다.

# 2. 맞춤 동화 생성(RAG)과 타입캐스트 낭독 제안

### 0. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 제안 | 아이가 좋아하는 동화를 고르면, 그 동화들의 특징을 검색·참조(RAG)해 **새 동화를 AI가 만들어 주고**, **타입캐스트(Typecast) TTS**로 읽어 주는 기능 |
| 출처 | 멘토링 자료 '주제2: 올인원 육아 앱 서비스' 중 "RAG 활용 (제안): 아이가 좋아하는 동화들을 선택 > 선택한 동화들을 바탕으로 한 AI 동화 생성 / 동화 읽어주는 건 (타입캐스트)" |
| 기획서와의 관계 | 기획서(p.2)의 "AI로 만든 오리지널 + 퍼블릭 도메인 재창작작" 전략을 **아이 한 명 한 명에게 맞춘 콘텐츠로 확장**하는 기능. 기획서의 나레이션(p.3, p.6)과 문장 타이밍도 그대로 이용 |
| 핵심 쟁점 | ① 저작권(무엇을 검색 대상으로 삼는가) ② 안전·검수(기획서의 '모든 콘텐츠 사람 검수' 원칙과의 충돌) ③ 비용(생성·TTS 호출) |
| 권장 방향 | **단계적 도입**: 1단계 취향 기반 추천(검색만) → 2단계 요청형 생성(검수 대기열) → 3단계 즉시 생성. MVP에는 1단계만 포함 권장 |

### 1. 제안 배경과 기대 효과

**왜 필요한가**
- 기획서의 MVP는 동화 20편이다. 아이는 같은 이야기를 반복해서 듣지만, 부모는 "새롭지만 아이가 좋아할 이야기"를 계속 찾아야 한다. (이 가정은 인터뷰 Q4, Q10, 추가 1에서 검증)
- 제작 인력이 1인 기준(기획서 p.10)이라 콘텐츠 수를 사람이 늘리는 데 한계가 있다. 취향 조합으로 이야기가 파생되면 같은 소재로 콘텐츠 수명이 늘어난다.
- 경쟁 앱(핑크퐁, 베이비버스 등)은 캐릭터 IP와 고정된 영상 라이브러리 중심이다. '내 아이 취향에 맞춘 새 이야기'는 차별화 후보가 될 수 있다. (경쟁 앱에 이 기능이 있는지는 미확인)

**기대 효과 (검증 전 가설)**
1. 재방문과 사용 시간 증가: 새 이야기가 계속 나온다.
2. 잠자리 사용 증가: "오늘은 토끼가 나오는 짧은 이야기" 같은 상황 맞춤이 가능하다.
3. 부모의 선택 부담 감소: 아이 취향 기반 추천이 자동으로 쌓인다.

### 2. 사용자 경험 흐름

부모 계정 기준으로 동작한다. 아이 개인정보는 기획서 원칙대로 별칭·생년월만 사용한다.

| 단계 | 화면 | 동작 | 비고 |
|---|---|---|---|
| 1 | 동화 탭 상단 '나만의 동화 만들기' | 진입 버튼. 홈의 '오늘의 추천' 카드에서도 진입 | 아이 프로필(월령) 선택 필수 |
| 2 | 좋아하는 동화 고르기 | 라이브러리에서 **3~5편** 선택. 즐겨찾기·이어 보기 이력이 있으면 미리 체크된 후보 제시 | 선택 가능한 책은 우리 라이브러리 안의 콘텐츠만 (3.1 참조) |
| 3 | 오늘의 이야기 조건 | 주제(친구, 동물, 잠자리 등), 길이(짧게/보통), 분위기(포근/신나는), 용도(잠자리용 여부) | 선택지 위주로 구성. 자유 입력은 MVP에서 제외 권장 |
| 4 | 생성 중 | 진행 표시(아웃라인 → 본문 → 안전 검사 → 낭독 준비). 대기 중 다른 탭 이동 가능, 완료 시 알림 | 미니 플레이어는 기존 오디오를 계속 재생 |
| 5 | 부모 미리보기·승인 | 요약과 전체 텍스트를 보여 주고 '아이에게 들려주기' 또는 '다시 만들기' | 부모 확인 단계가 안전 장치 중 하나 |
| 6 | 뷰어·낭독 | 기존 동화 뷰어(그림책 모드, 오디오 모드, 문장 하이라이트)와 동일. 타입캐스트 음성으로 읽어 줌 | 잠자리 모드(타이머, 볼륨 감소) 연동 |
| 7 | 보관·피드백 | '만든 동화'로 보관함에 저장, 즐겨찾기, 오프라인 저장. '이상해요' 신고 버튼 | 신고는 검수 대기열로 전달 |

**잠자리 모드와의 연결**: 용도를 '잠자리용'으로 고르면 짧고 조용한 결말의 이야기를 만들고, 낭독은 느린 속도와 낮은 감정 강도로 합성한다(5.2).

### 3. RAG 구조

RAG는 "생성 전에 관련 자료를 검색해 모델에게 참고 자료로 주는 방식"이다. 여기서는 아이가 고른 동화의 **분위기·구조·어휘 수준**을 모델에게 알려 주는 용도다. 원문을 베끼게 하려는 것이 아니다.

#### 3.1 검색 대상(코퍼스)과 저작권 원칙

| 구분 | 포함 여부 | 설명 |
|---|---|---|
| 자체 제작 오리지널 동화 | 포함 | 기획서 MVP 10편. 권리가 우리에게 있음 |
| 퍼블릭 도메인 동화 | 포함 | 저작권 보호기간이 끝난 작품. 한국 저작권법은 저작자 사후 70년이 기준이므로, **번역본·편집본의 권리는 별도**로 확인해야 함 |
| 이용 허락이 명시된 공공 자료 | 조건부 | 공공누리 등 이용 조건을 작품별로 확인하고 기록 |
| 시판 동화(저작권 보호 중) | **제외** | 부모가 "우리 아이가 좋아하는 책"으로 이름을 입력해도 해당 본문을 코퍼스에 넣거나 생성에 이용하지 않음 |

- 기획서 p.8의 체크리스트("원작 퍼블릭 도메인 여부를 작품별로 확인", "원작 출처와 도구 라이선스 기록")를 그대로 적용한다.
- 선택 UI에서 라이브러리 밖의 책을 고를 수 없게 해서, 사용자가 저작물을 몰래 요구하는 경로를 구조적으로 막는다.
- 이후 외부 도서를 다루려면 출판사 제휴 또는 허락이 필요하다. 이는 별도 협의 사항이다.

#### 3.2 수집·가공 (인제스트)

1. **원문 정제**: 오탈자 수정, 현대어 정리, 불필요한 서문 제거.
2. **장면(페이지) 단위로 나누기**: 기획서의 `StoryPage` 구조와 맞춘다. 한 청크는 보통 한 장면(1~3 문장).
3. **메타데이터 부여**: 월령 범위, 주제, 등장인물 유형, 분위기, 교훈/주제, 반복구 유무, 문장 길이, 어휘 수준, 출처·라이선스, 검수 상태, 안전 등급.
4. **임베딩과 저장**: 한국어를 지원하는 임베딩 모델(후보를 평가해 선정)로 청크를 벡터화하고 PostgreSQL의 벡터 확장(pgvector)에 저장한다. 기획서의 서버 구성(NestJS + Postgres)을 그대로 쓸 수 있다.
5. **스타일 프로필 추출**: 동화 한 편마다 LLM으로 아래 구조화 정보를 뽑아 JSON으로 저장한다. 사람이 샘플 검수한다.

```json
{
  "themes": ["우정", "나눔"],
  "character_types": ["작은 동물", "친근한 어른"],
  "structure": "반복형",
  "tone": "포근함",
  "avg_sentence_length": 9,
  "onomatopoeia": ["퐁당", "살금살금"],
  "ending": "안심하는 결말",
  "age_range_months": [24, 48]
}
```

#### 3.3 아이 취향 프로필

- 아이가 고른 3~5편의 스타일 프로필을 합쳐 '취향 프로필'을 만든다 (공통 주제, 자주 나온 분위기, 선호 구조 등).
- 저장하는 것은 **선택한 콘텐츠 ID와 요약 태그**뿐이다. 아이 이름, 사진, 음성은 저장하지 않는다.
- 부모가 취향 프로필을 보고 삭제하거나 초기화할 수 있게 한다.

#### 3.4 검색

- 입력: 취향 프로필 + 오늘의 조건(주제, 길이, 분위기, 용도).
- **필터(필수)**: 월령 범위, 안전 등급, 검수 완료 여부. 필터를 통과한 청크만 후보가 된다.
- **검색**: 벡터 유사도와 메타데이터 일치를 합친 하이브리드 검색으로 상위 k개의 장면·요소를 고른다.
- 선택한 책들에서 골고루 가져오도록 책별 상한을 둔다(한 책에만 쏠리지 않게).

#### 3.5 생성 단계

한 번에 길게 쓰게 하지 않고 단계를 나눠 품질을 관리한다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| ① 아웃라인 | 검색된 요소를 참고해 새 등장인물, 새 사건, 새 결말로 이야기 뼈대 작성 | 페이지별 한 줄 줄거리 |
| ② 본문 작성 | 월령별 규칙(3.6)에 맞춰 페이지별 본문 작성 | 페이지별 텍스트 |
| ③ 안전·품질 검사 | 4장의 자동 검사 | 통과/재작성 |
| ④ 화자·문장 분할 | 서술과 대사를 나누고 문장 단위로 분할 | 문장 목록(화자, 감정 힌트) |
| ⑤ 낭독 합성 | 타입캐스트 호출, 타임스탬프 수집 | 오디오, 문장 타이밍 |
| ⑥ 삽화(선택) | 3.7 참조 | 페이지 이미지 |

**프롬프트 원칙**
- "참고 자료의 문장을 그대로 쓰지 말고, 분위기와 구조만 참고해 새 이야기를 쓴다"를 명시한다.
- 검색된 원문은 모델에게 **요약 형태의 요소**로 주고, 긴 원문 인용은 피한다.
- 월령, 금지 표현, 길이 제한, 결말 톤을 규칙으로 넣는다.
- 프롬프트와 모델 버전을 기록해 문제 발생 시 추적할 수 있게 한다.

#### 3.6 월령별 작성 규칙 (제안값, 전문가·부모 검증 필요)

| 월령 | 페이지 수 | 페이지당 문장 | 문장 특징 | 구조 |
|---|---|---|---|---|
| 0~12개월 | 3~5 | 1 | 의성의태어와 반복 위주, 짧은 호흡 | 같은 패턴 반복 |
| 13~24개월 | 5~7 | 1~2 | 쉬운 단어, 반복구 | 간단한 반복과 작은 변화 |
| 25~36개월 | 6~9 | 2~3 | 일상 소재, 간단한 대화 | 시작-사건-해결 |
| 37~60개월 | 8~12 | 3~5 | 감정 표현, 대화 포함 | 기승전결, 따뜻한 결말 |

위 숫자는 설계 출발점이며 근거 자료가 있는 값이 아니다. 인터뷰와 시범 제작에서 조정한다.

#### 3.7 삽화

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 기존 삽화 조합 | 우리 캐릭터 시트와 배경·장면 템플릿 라이브러리에서 조합 | 품질 일관, 비용 낮음, 검수 쉬움 | 새 장면 표현이 제한됨 |
| B. 즉석 이미지 생성 | 기획서 p.6 파이프라인(캐릭터 시트 + 이미지 편집 모델)을 호출 | 표현 자유 | 손·얼굴 왜곡 위험, 비용·시간, 검수 부담 |
| C. 오디오 전용 | 이미지 없이 낭독만 제공 | 가장 단순, 잠자리에 적합 | 그림책 경험 약함 |

권장: 1~2단계는 **A 또는 C**로 시작하고, B는 품질 검수 체계가 갖춰진 뒤에 도입한다.

### 4. 안전·품질 가드레일

**가장 중요한 충돌**: 기획서(p.6, p.8)는 "모든 콘텐츠는 사람 검수를 거쳐야 공개"된다고 정했다. 아이마다 즉석으로 만드는 이야기는 이 원칙과 충돌한다. 아래 세 가지 중 하나를 결정해야 한다.

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| ① 사전 검수형 | 운영자가 취향 조합 템플릿을 미리 생성·검수해 두고, 사용자는 그중에서 매칭 | 기획서 원칙 유지, 가장 안전 | 개인화 정도가 낮음 |
| ② 검수 대기열형 | 요청 → 자동 검사 → 사람 검수 → 알림(수 시간) | 원칙 유지, 개인화 가능 | 대기, 운영 인력 필요 |
| ③ 자동 검사 + 부모 승인형 | 자동 검사 통과 후 부모가 미리보기로 승인, 사후 신고·샘플 검수 | 즉시 재생 | 기획서 원칙 완화, 사고 위험 가장 큼 |

**권장**: 1단계 ①, 2단계 ②, 3단계 ③은 충분한 검증 이후 판단.

**자동 검사 체크리스트** (기획서 p.8 콘텐츠 검수 기준을 확장)
- [ ] 무서운 표현·장면, 폭력, 죽음·상실, 위험 행동 모사
- [ ] 편견·차별 표현, 성별·외모 고정관념
- [ ] 실제 브랜드·유명 캐릭터·실명 포함 여부
- [ ] 원문과의 유사도 (연속 문장 일치 여부, 임계값 초과 시 재작성)
- [ ] 월령 적합 어휘와 문장 길이
- [ ] 아이 개인정보 포함 여부 (이름, 주소 등)
- [ ] 이야기 구조 완결성 (끝맺음이 없는 이야기, 교훈 강요)
- [ ] 이유식 등 건강 정보를 사실처럼 단정하는 문장
- [ ] 사용자 입력이 모델 지시를 바꾸려는 시도(프롬프트 주입) – 자유 입력을 받는 경우

**운영 장치**
- 모든 생성 결과에 생성 요청 ID, 모델·프롬프트 버전, 검사 결과, 유사도 점수를 저장한다.
- '이상해요' 신고는 즉시 해당 콘텐츠를 비공개 처리하고 검수 대기열로 보낸다.
- 'AI가 만든 이야기' 표시를 화면에 분명히 한다. (부모의 AI 수용도는 설문 Part E와 추가 문항으로 확인)
- Apple 키즈, Google Families 정책에서 생성형 AI 콘텐츠에 대한 요건을 출시 전에 확인한다. (기획서 p.8의 항목에 이미 포함)

### 5. 타입캐스트(Typecast) 낭독

#### 5.1 확인된 사양 (웹 검색으로 확인한 공식 문서 요약)

| 항목 | 확인된 내용 |
|---|---|
| 모델·언어 | 최신 모델 ssfm-v30, ssfm-v21 지원. 37개 언어 소개 |
| 감정 제어 | ssfm-v30은 **프리셋**(normal, happy, sad, angry, whisper, toneup, tonedown)과 **스마트 모드**(앞뒤 문맥으로 AI가 감정 추론) 제공. 프리셋은 강도 지정 가능 |
| 속도·음높이·음량 | 템포 0.5~2.0배, 피치 -12~+12 반음, 라우드니스(LUFS) 조절 |
| 오디오 포맷 | WAV, MP3. 문서상 MP3가 필요하면 WAV 생성 후 서버/앱에서 변환하도록 안내 |
| 스트리밍 | 청크 오디오 스트리밍 엔드포인트 제공, 응답 속도 200ms 소개(공급사 주장) |
| 타임스탬프 | 단어·문자 단위 정렬 데이터 제공. 자막·노래방식 하이라이트·립싱크용으로 안내 |
| SDK | Python, JavaScript/TypeScript, PHP, Ruby, C/C++, Dart, Java 등 공식 SDK 안내. 문서에서 **API 키는 백엔드를 거쳐 호출**하도록 권장 |
| SSML | 검색에서는 지원 여부를 확인하지 못함 → 공식 API 레퍼런스에서 확인 필요 |

출처는 문서 끝의 링크를 참고하세요. 요금, 속도 파라미터의 실제 필드명, 화자(보이스) 목록과 어린이 콘텐츠 적합 여부는 확인하지 못했습니다.

**기획서 요구와의 대응**
- 기획서 p.3 "나레이션 + 하이라이트" → 타임스탬프로 문장·단어 하이라이트 구현 가능성이 높음.
- 기획서 p.5 `StoryPage`의 "오디오 타이밍" → 타임스탬프 응답을 저장.
- 기획서 p.6 "나레이션: TTS·문장 타이밍" → 이 기능과 동일한 공정.
- 기획서 p.3 오프라인 저장 → 합성한 오디오를 파일로 저장해 다운로드 제공.

#### 5.2 낭독 설계

| 요소 | 설계 (제안값, 실제 청취 테스트로 조정) |
|---|---|
| 화자 | 내레이터 1명 + 주요 등장인물 최대 2명. 월령이 낮을수록 화자를 줄여 혼란 방지 |
| 보이스 선정 | 어린이 대상 콘텐츠에 적합한 차분하고 또렷한 보이스를 청취 테스트로 선정. 보이스 ID와 이용 조건을 기록 |
| 일반 낭독 | 감정 normal 또는 스마트 모드, 템포 1.0 전후 |
| 잠자리 모드 | whisper 또는 낮은 강도 프리셋, 템포를 소폭 낮춤(예: 0.85~0.9), 마지막 문장은 더 느리게 |
| 의성의태어·반복구 | 문장 단위로 따로 합성해 억양을 확인, 필요 시 발음 사전 적용 |
| 고유명사 | 등장인물 이름 발음 사전을 만들어 오독을 방지 |
| 길이 관리 | 문장(또는 문단) 단위로 합성해 이어 붙임. 실패한 문장만 재합성 |

#### 5.3 오디오 파이프라인

```
본문 → 문장 분할 → 화자/감정 태깅(LLM) → 타입캐스트 호출(문장 단위)
     → 오디오(WAV) + 타임스탬프 → 후처리(무음 보정, 음량 통일, MP3 변환)
     → 스토리지(R2/S3) 저장 → StoryPage.audio 타이밍 기록 → CDN으로 서빙
```

- **캐시**: 사전 제작 콘텐츠와 생성된 이야기 모두 한 번 합성한 파일을 저장해 재생할 때 재호출하지 않는다 (비용 절감).
- **지연 관리**: 생성 직후 첫 문장부터 스트리밍 재생을 쓸 수 있으나, 오프라인 저장과 하이라이트를 위해서는 완성본 파일을 별도로 만든다.
- **실패 대응**: 합성 실패 시 텍스트 모드로 먼저 보여 주고 오디오는 재시도한다. 서비스 장애 시를 대비해 사전 제작 콘텐츠는 이미 저장된 오디오를 쓴다.
- **보안**: API 키는 서버에만 두고, 앱에서 직접 호출하지 않는다.

#### 5.4 계약·정책 확인 필요

### 7. 단계별 도입안

| 단계 | 내용 | 검수 방식 | 비고 |
|---|---|---|---|
| 1단계 (MVP) | 아이가 고른 동화 기반 **취향 추천**(검색만, 생성 없음). 타입캐스트 낭독은 사전 제작 콘텐츠에 적용 | 기존과 동일(전량 검수) | 기획서 10주 일정 안에 포함 가능 |

| 3단계 | 즉시 생성(자동 검사 + 부모 승인), 삽화 즉석 생성 검토 | 자동 + 사후 샘플 검수 | 사고 위험이 가장 커서 충분한 데이터 확보 후 판단 |

1단계에서 쌓이는 **선택 이력과 취향 태그**가 2단계 이후 품질의 기반이 된다.

|---|---|
| 정확도 | 울음 **원인** 분류는 정확도가 제한적이다. 공개 데이터셋(Donate-a-Cry 등)은 규모가 작고 라벨에 잡음이 많다 |
| 규제 | 질병·통증 진단을 표방하면 의료기기 규제(식약처) 이슈가 생긴다. 서비스는 **'감지 알림·참고용'으로 한정**해야 한다 |
| 미탐 | 위험 상황을 놓치는 **미탐이 오탐보다 치명적**이다. 실제 가정의 소음과 기기 차이로 성능이 떨어질 수 있다 |

### 3. 한계를 줄이는 딥러닝 방법

| 방법 | 내용 | 기대 효과 |
|---|---|---|
| 문제 단계화 | 울음 감지 → 강도 분류 → 원인 후보 제시(상위 2~3개) 순서로 접근 | 어려운 문제를 쉬운 단계부터 확보 |
| 사전학습 + 도메인 적응 | AudioSet 사전학습 모델을 파인튜닝하고, 라벨 없는 울음 데이터로 자기지도 학습 | 적은 라벨로도 성능 확보 |
| 멀티모달 퓨전 | 오디오 임베딩에 수유·수면·기저귀 기록을 결합해 원인 추정 | 원인 추정 정확도 향상 |
| 개인화 | 아기별 평소 울음 기준선을 학습해 이탈을 탐지하고, 부모 피드백(맞음/틀림)으로 온디바이스 보정 | 개인차와 환경 차 완화 |
| 불확실성 관리 | 확신도 보정(Calibration)과 기권 옵션, **감지는 재현율 우선·원인 분류는 정밀도 우선**, 위험 경고는 규칙을 병행 | 오탐·미탐 균형 관리 |
| 라벨·증강 | 행동 기반 약한 라벨 + 전문가 검수 평가셋, 소음 믹싱·SpecAugment로 환경 강건성 확보 | 라벨 부족과 환경 변화 대응 |

### 4. 우리 기획에 적용할 때 (제안)

아래는 위 검토를 기획서와 연결해 제가 정리한 제안입니다. 근거 자료가 있는 수치는 아닙니다.

**단계별 범위**
| 단계 | 기능 | 비고 |
|---|---|---|
| A | 울음 감지 알림(울고 있음을 부모에게 알림) | 가장 단순. 온디바이스 처리 권장 |
| B | 울음 강도 분류(약함/보통/강함) | 부모의 기록 보조 |
| C | 원인 후보 2~3개 제시 + 수유·수면·기저귀 기록 결합 | 반드시 '참고용' 표기, 부모 피드백 수집 |
| 제외 | 질병·통증 진단, 응급 판단 | 규제와 책임 문제로 범위 밖 |

**화면 문구 원칙**
- "진단이 아닙니다. 아이 상태가 걱정되면 소아과나 119에 연락하세요"를 항상 표시한다. (기획서 이유식 화면의 소아과 상담 안내와 같은 방식)
- 확신이 낮으면 "잘 모르겠어요"로 기권하고, 틀린 추정을 단정하지 않는다.

**평가 기준(조사 전에 정할 것)**
- 감지는 재현율 우선으로 목표치를 합의한다(예: 놓친 울음 비율의 상한).
- 평가는 학습에 쓰지 않은 가정 환경 녹음, 전문가 검수 라벨로 한다.
- 소음 환경(TV, 가전, 형제자매, 반려동물)별 성능을 따로 본다.

**데이터·개인정보**
- 아기 음성을 서버에 저장할지, 기기 안에서만 처리할지 먼저 정한다.
- 학습 데이터를 모으려면 부모 동의, 보관 기간, 삭제 방법을 명시해야 한다. 기획서의 "아이 정보 최소 수집" 원칙과 맞춰야 한다.
- 공개 데이터셋은 라이선스와 상업 이용 가능 여부를 확인한다.

### 5. 확인이 필요한 사항

# 4. 부모 심층 인터뷰 가이드 (육아 앱 기획 검증)

- 대상: 0~5세 자녀를 둔 부모 5~8명 (0~12개월 2명 이상 / 13~36개월 2명 / 37개월 이상 1~2명)
- 시간: 40~50분, 온라인(화상) 또는 대면
- 사례: 소정의 답례(예: 기프티콘 1~2만 원)
- 원칙: 아이 이름·사진·정확한 생년월일은 묻지 않는다. **월령(개월 수)만** 묻는다.
- 진행 팁: 앱 아이디어를 먼저 설명하지 않는다. 과거 행동 → 불편 → 개념 반응 순서로 진행한다. "~하실 것 같으세요?"보다 "최근에 ~하셨을 때 어땠나요?"를 쓴다.

### 0. 도입 (3분)
- 취지 설명: "육아 앱을 기획 중이며, 정답은 없고 솔직한 경험을 듣고 싶습니다."
- 녹음 동의, 개인정보 비식별 처리, 언제든 중단 가능함을 안내한다.

### 1. 가족 상황 (5분)
1. 자녀가 몇 명이고 막내가 몇 개월인가요? (월령만)
2. 평일 하루가 어떻게 흘러가는지 간단히 말씀해 주세요.
3. 육아에서 요즘 가장 시간이 부족하거나 힘든 순간은 언제인가요?

### 2. 콘텐츠 이용 경험: 동화·동요 (12분)
4. **지난주**에 아이에게 영상·음악·동화를 보여주거나 들려준 상황을 하나만 처음부터 끝까지 이야기해 주세요. (언제/어디서/어떤 기기/무엇을/얼마나/왜)
5. 지금 쓰는 앱·서비스는 무엇인가요? 선택한 이유는 무엇인가요?
6. 마음에 드는 점과 불편하거나 걱정되는 점은 무엇인가요? (광고, 자극적인 영상, 시간 관리, 비용, 콘텐츠 부족 등)
7. 잠자리, 외출, 식사 때 콘텐츠를 어떻게 쓰시나요? 그때 가장 아쉬운 점은 무엇인가요?
8. 새로운 콘텐츠는 어떻게 찾으세요? (검색, 추천, 지인, 카페 등)
9. 유료 서비스를 써 보신 적이 있나요? 있다면 무엇이었고 왜 결제/해지하셨나요?
10. 아이가 가장 오래 반복해서 보거나 듣는 콘텐츠는 무엇이고, 그 이유는 무엇이라고 보시나요?

### 3. 이유식 경험 (10분) ※이유식 시기(약 4~24개월) 경험이 있는 부모
11. 이유식을 시작할 때 정보는 어디서 얻으셨나요?
12. 새로운 재료를 처음 먹일 때 어떤 절차로 하셨나요? 그 내용을 기록하셨나요? 어떻게요? (메모, 앱, 머릿속 등)
13. 반응(알레르기 의심 등)을 확인하고 기록하는 과정에서 불편했던 점은 무엇인가요?
14. 레시피를 찾고 따라 하는 과정에서 어려웠던 점은 무엇인가요? (재료 구하기, 보관, 단계별 양 등)
15. 이유식 정보를 믿을 수 있다고 판단하는 기준은 무엇인가요? 어디의 정보를 가장 신뢰하세요?

### 4. 앱 사용 습관·구성 (5분)
16. 육아 관련 앱을 몇 개 쓰시나요? 앱이 많아서 불편한 점이 있나요?
17. 동화·동요·이유식이 **한 앱**에 있다면 어떤 경우에 좋고, 어떤 경우에 불편할 것 같나요? (솔직하게)
18. 앱을 삭제했던 경험이 있다면 이유는 무엇이었나요?

### 5. 컨셉 반응 (10분) ※이때 처음 아이디어를 보여준다
화면에 기획서 p.2~4의 요약 카드 또는 목업을 공유한다.

19. 이 앱이 무엇을 하는 앱이라고 이해하셨나요? 본인 말로 설명해 보세요.
20. 가장 끌리는 부분과 가장 의문스러운 부분은 무엇인가요?
21. **잠자리 모드**(화면 어두워짐 + 15/30/45분 타이머 + 볼륨 서서히 감소)는 어떤가요? 실제로 쓸 상황이 있나요? 있다면 언제인가요?
22. **새 재료 기록**(처음 먹인 날짜·재료·반응 → 달력 누적)은 어떤가요? 지금 방식과 비교해 어떤가요?
23. 광고가 없고 무료라면, 오히려 걱정되는 부분이 있나요? (수익 구조, 안정성 등)

### 6. AI 제작 콘텐츠 수용도 (8분) ※핵심 가설
24. "AI가 만든 동화/동요/이미지"라는 말을 들으면 어떤 느낌이 드세요?
25. (샘플 보여주기) 같은 그림책 2장을 보여드릴게요. 하나는 AI 제작, 하나는 사람이 그렸다고 알려드립니다. 어떻게 느끼시나요? 아이에게 보여줄 수 있나요? 
    - 차이를 못 느꼈다면 어떤 표기가 있으면 안심이 될까요?
26. 어떤 조건이면 아이에게 보여줄 수 있고, 어떤 조건이면 안 보여줄까요? (사람 검수 표기, 출처 공개, 소아과 전문가 감수, 일러스트레이터 협업 등)
27. 이유식 레시피를 AI가 구성하고 공공 영양 가이드를 바탕으로 사람이 검수했다면 신뢰하실 수 있나요? 어떤 문구가 있어야 하나요?

### 6-2. 맞춤 동화 생성 컨셉 (선택, 8분)
컨셉 설명: "아이가 좋아하는 동화를 3~5권 고르면, 비슷한 분위기의 새 이야기를 AI가 만들어 주고 AI 목소리로 읽어 주는 기능입니다. 아이 개인정보는 쓰지 않습니다."

추가 1. 아이가 요즘 가장 좋아하는 동화나 캐릭터는 무엇인가요? 같은 이야기를 반복해서 읽어 달라고 하나요? 그럴 때 어떠세요?
추가 2. 위 기능이 있다면 어떤 상황에서 쓰실 것 같나요? 아니면 쓰지 않을 이유가 있나요? 기존 방식(새 책 사기, 영상 찾기)과 비교하면 어떤가요?
추가 3. 새로 만들어진 이야기를 아이에게 들려주기 전에 직접 확인하고 싶으신가요? 어디까지 확인하고 싶으세요? (전체 읽기 / 요약 / 안전 표시만) 확인이 끝날 때까지 몇 시간 기다려야 한다면 괜찮으신가요?
추가 4. 이야기를 읽어 주는 목소리가 AI 목소리라면 어떻게 느껴지세요? 부모 목소리 녹음, AI 목소리, 성우 녹음 중 무엇을 선호하시나요? 잠자리에는 어떤가요? (샘플 음성 1~2개 들려주기)
추가 5. 걱정되는 점이 있다면 무엇인가요? (무서운 내용, 기존 동화와 비슷함, 이름 같은 개인정보, 화면·소리 시간 등) 이야기에 아이 이름이 들어가는 것은 어떻게 생각하세요?

### 7. 가격·마무리 (5분)
28. 이런 앱이 있다면 무료 외에 어떤 형태(광고 없음 유료, 구독, 콘텐츠 단건 구매 등)를 선택하실 것 같나요? 월 어느 정도까지가 부담 없는 금액인가요?
29. 지금까지 이야기에서 빠진 것, 꼭 있어야 할 기능이 있나요?
30. 비슷한 상황의 다른 부모를 소개해 주실 수 있나요?
