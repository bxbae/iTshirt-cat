## 1. 제안 배경과 기대 효과

**왜 필요한가**
- 기획서의 MVP는 동화 20편이다. 아이는 같은 이야기를 반복해서 듣지만, 부모는 "새롭지만 아이가 좋아할 이야기"를 계속 찾아야 한다. (이 가정은 인터뷰 Q4, Q10, 추가 1에서 검증)
- 제작 인력이 1인 기준(기획서 p.10)이라 콘텐츠 수를 사람이 늘리는 데 한계가 있다. 취향 조합으로 이야기가 파생되면 같은 소재로 콘텐츠 수명이 늘어난다.
- 경쟁 앱(핑크퐁, 베이비버스 등)은 캐릭터 IP와 고정된 영상 라이브러리 중심이다. '내 아이 취향에 맞춘 새 이야기'는 차별화 후보가 될 수 있다. (경쟁 앱에 이 기능이 있는지는 미확인)

**기대 효과 (검증 전 가설)**
1. 재방문과 사용 시간 증가: 새 이야기가 계속 나온다.
2. 잠자리 사용 증가: "오늘은 토끼가 나오는 짧은 이야기" 같은 상황 맞춤이 가능하다.
3. 부모의 선택 부담 감소: 아이 취향 기반 추천이 자동으로 쌓인다.

## 2. 사용자 경험 흐름

부모 계정 기준으로 동작한다. 아이 개인정보는 기획서 원칙대로 별칭·생년월만 사용한다.

| 단계 | 화면 | 동작 | 비고 |
|---|---|---|---|
| 1 | 동화 탭 상단 '나만의 동화 만들기' | 진입 버튼. 홈의 '오늘의 추천' 카드에서도 진입 | 아이 프로필(월령) 선택 필수 |
| 2 | 좋아하는 동화 고르기 | 라이브러리에서 **3~5편** 선택. 즐겨찾기·이어 보기 이력이 있으면 미리 체크된 후보 제시 | 선택 가능한 책은 우리 라이브러리 안의 콘텐츠만 (3.1 참조) |
| 3 | 오늘의 이야기 조건 | 주제(친구, 동물, 잠자리 등), 길이(짧게/보통), 분위기(포근/신나는), 용도(잠자리용 여부) | 선택지 위주로 구성. 자유 입력은 MVP에서 제외 권장 |
| 4 | 생성 중 | 진행 표시(아웃라인 → 본문 → 안전 검사 → 낭독 준비). 대기 중 다른 탭 이동 가능, 완료 시 알림 | 미니 플레이어는 기존 오디오를 계속 재생 |
| 5 | 부모 미리보기·승인 | 요약과 전체 텍스트를 보여 주고 '아이에게 들려주기' 또는 '다시 만들기' | 부모 확인 단계가 안전 장치 중 하나 |
| 6 | 뷰어·낭독 | 기존 동화 뷰어(그림책 모드, 오디오 모드, 문장 하이라이트)와 동일. 타입캐스트 음성으로 읽어 줌 | 잠자리 모드(타이머, 볼륨 감소) 연동 |
| 7 | 보관·피드백 | '만든 동화'로 보관함에 저장, 즐겨찾기, 오프라인 저장. '이상해요' 신고 버튼 | 신고는 검수 대기열로 전달 |

**잠자리 모드와의 연결**: 용도를 '잠자리용'으로 고르면 짧고 조용한 결말의 이야기를 만들고, 낭독은 느린 속도와 낮은 감정 강도로 합성한다(5.2).

## 3. RAG 구조

RAG는 "생성 전에 관련 자료를 검색해 모델에게 참고 자료로 주는 방식"이다. 여기서는 아이가 고른 동화의 **분위기·구조·어휘 수준**을 모델에게 알려 주는 용도다. 원문을 베끼게 하려는 것이 아니다.

### 3.1 검색 대상(코퍼스)과 저작권 원칙

| 구분 | 포함 여부 | 설명 |
|---|---|---|
| 자체 제작 오리지널 동화 | 포함 | 기획서 MVP 10편. 권리가 우리에게 있음 |
| 퍼블릭 도메인 동화 | 포함 | 저작권 보호기간이 끝난 작품. 한국 저작권법은 저작자 사후 70년이 기준이므로, **번역본·편집본의 권리는 별도**로 확인해야 함 |
| 이용 허락이 명시된 공공 자료 | 조건부 | 공공누리 등 이용 조건을 작품별로 확인하고 기록 |
| 시판 동화(저작권 보호 중) | **제외** | 부모가 "우리 아이가 좋아하는 책"으로 이름을 입력해도 해당 본문을 코퍼스에 넣거나 생성에 이용하지 않음 |

- 기획서 p.8의 체크리스트("원작 퍼블릭 도메인 여부를 작품별로 확인", "원작 출처와 도구 라이선스 기록")를 그대로 적용한다.
- 선택 UI에서 라이브러리 밖의 책을 고를 수 없게 해서, 사용자가 저작물을 몰래 요구하는 경로를 구조적으로 막는다.
- 이후 외부 도서를 다루려면 출판사 제휴 또는 허락이 필요하다. 이는 별도 협의 사항이다.

### 3.2 수집·가공 (인제스트)

1. **원문 정제**: 오탈자 수정, 현대어 정리, 불필요한 서문 제거.
2. **장면(페이지) 단위로 나누기**: 기획서의 `StoryPage` 구조와 맞춘다. 한 청크는 보통 한 장면(1~3 문장).
3. **메타데이터 부여**: 월령 범위, 주제, 등장인물 유형, 분위기, 교훈/주제, 반복구 유무, 문장 길이, 어휘 수준, 출처·라이선스, 검수 상태, 안전 등급.
4. **임베딩과 저장**: 한국어를 지원하는 임베딩 모델(후보를 평가해 선정)로 청크를 벡터화하고 PostgreSQL의 벡터 확장(pgvector)에 저장한다. 기획서의 서버 구성(NestJS + Postgres)을 그대로 쓸 수 있다.
5. **스타일 프로필 추출**: 동화 한 편마다 LLM으로 아래 구조화 정보를 뽑아 JSON으로 저장한다. 사람이 샘플 검수한다.

```json
{
  "themes": ["우정", "나눔"],
  "character_types": ["작은 동물", "친근한 어른"],
  "structure": "반복형",
  "tone": "포근함",
  "avg_sentence_length": 9,
  "onomatopoeia": ["퐁당", "살금살금"],
  "ending": "안심하는 결말",
  "age_range_months": [24, 48]
}
```

### 3.3 아이 취향 프로필

- 아이가 고른 3~5편의 스타일 프로필을 합쳐 '취향 프로필'을 만든다 (공통 주제, 자주 나온 분위기, 선호 구조 등).
- 저장하는 것은 **선택한 콘텐츠 ID와 요약 태그**뿐이다. 아이 이름, 사진, 음성은 저장하지 않는다.
- 부모가 취향 프로필을 보고 삭제하거나 초기화할 수 있게 한다.

### 3.4 검색

- 입력: 취향 프로필 + 오늘의 조건(주제, 길이, 분위기, 용도).
- **필터(필수)**: 월령 범위, 안전 등급, 검수 완료 여부. 필터를 통과한 청크만 후보가 된다.
- **검색**: 벡터 유사도와 메타데이터 일치를 합친 하이브리드 검색으로 상위 k개의 장면·요소를 고른다.
- 선택한 책들에서 골고루 가져오도록 책별 상한을 둔다(한 책에만 쏠리지 않게).

### 3.5 생성 단계

한 번에 길게 쓰게 하지 않고 단계를 나눠 품질을 관리한다.

| 단계 | 내용 | 산출물 |
|---|---|---|
| ① 아웃라인 | 검색된 요소를 참고해 새 등장인물, 새 사건, 새 결말로 이야기 뼈대 작성 | 페이지별 한 줄 줄거리 |
| ② 본문 작성 | 월령별 규칙(3.6)에 맞춰 페이지별 본문 작성 | 페이지별 텍스트 |
| ③ 안전·품질 검사 | 4장의 자동 검사 | 통과/재작성 |
| ④ 화자·문장 분할 | 서술과 대사를 나누고 문장 단위로 분할 | 문장 목록(화자, 감정 힌트) |
| ⑤ 낭독 합성 | 타입캐스트 호출, 타임스탬프 수집 | 오디오, 문장 타이밍 |
| ⑥ 삽화(선택) | 3.7 참조 | 페이지 이미지 |

**프롬프트 원칙**
- "참고 자료의 문장을 그대로 쓰지 말고, 분위기와 구조만 참고해 새 이야기를 쓴다"를 명시한다.
- 검색된 원문은 모델에게 **요약 형태의 요소**로 주고, 긴 원문 인용은 피한다.
- 월령, 금지 표현, 길이 제한, 결말 톤을 규칙으로 넣는다.
- 프롬프트와 모델 버전을 기록해 문제 발생 시 추적할 수 있게 한다.

### 3.6 월령별 작성 규칙 (제안값, 전문가·부모 검증 필요)

| 월령 | 페이지 수 | 페이지당 문장 | 문장 특징 | 구조 |
|---|---|---|---|---|
| 0~12개월 | 3~5 | 1 | 의성의태어와 반복 위주, 짧은 호흡 | 같은 패턴 반복 |
| 13~24개월 | 5~7 | 1~2 | 쉬운 단어, 반복구 | 간단한 반복과 작은 변화 |
| 25~36개월 | 6~9 | 2~3 | 일상 소재, 간단한 대화 | 시작-사건-해결 |
| 37~60개월 | 8~12 | 3~5 | 감정 표현, 대화 포함 | 기승전결, 따뜻한 결말 |

위 숫자는 설계 출발점이며 근거 자료가 있는 값이 아니다. 인터뷰와 시범 제작에서 조정한다.

### 3.7 삽화

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 기존 삽화 조합 | 우리 캐릭터 시트와 배경·장면 템플릿 라이브러리에서 조합 | 품질 일관, 비용 낮음, 검수 쉬움 | 새 장면 표현이 제한됨 |
| B. 즉석 이미지 생성 | 기획서 p.6 파이프라인(캐릭터 시트 + 이미지 편집 모델)을 호출 | 표현 자유 | 손·얼굴 왜곡 위험, 비용·시간, 검수 부담 |
| C. 오디오 전용 | 이미지 없이 낭독만 제공 | 가장 단순, 잠자리에 적합 | 그림책 경험 약함 |

권장: 1~2단계는 **A 또는 C**로 시작하고, B는 품질 검수 체계가 갖춰진 뒤에 도입한다.

## 4. 안전·품질 가드레일

**가장 중요한 충돌**: 기획서(p.6, p.8)는 "모든 콘텐츠는 사람 검수를 거쳐야 공개"된다고 정했다. 아이마다 즉석으로 만드는 이야기는 이 원칙과 충돌한다. 아래 세 가지 중 하나를 결정해야 한다.

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| ① 사전 검수형 | 운영자가 취향 조합 템플릿을 미리 생성·검수해 두고, 사용자는 그중에서 매칭 | 기획서 원칙 유지, 가장 안전 | 개인화 정도가 낮음 |
| ② 검수 대기열형 | 요청 → 자동 검사 → 사람 검수 → 알림(수 시간) | 원칙 유지, 개인화 가능 | 대기, 운영 인력 필요 |
| ③ 자동 검사 + 부모 승인형 | 자동 검사 통과 후 부모가 미리보기로 승인, 사후 신고·샘플 검수 | 즉시 재생 | 기획서 원칙 완화, 사고 위험 가장 큼 |

**권장**: 1단계 ①, 2단계 ②, 3단계 ③은 충분한 검증 이후 판단.

**자동 검사 체크리스트** (기획서 p.8 콘텐츠 검수 기준을 확장)
- [ ] 무서운 표현·장면, 폭력, 죽음·상실, 위험 행동 모사
- [ ] 편견·차별 표현, 성별·외모 고정관념
- [ ] 실제 브랜드·유명 캐릭터·실명 포함 여부
- [ ] 원문과의 유사도 (연속 문장 일치 여부, 임계값 초과 시 재작성)
- [ ] 월령 적합 어휘와 문장 길이
- [ ] 아이 개인정보 포함 여부 (이름, 주소 등)
- [ ] 이야기 구조 완결성 (끝맺음이 없는 이야기, 교훈 강요)
- [ ] 이유식 등 건강 정보를 사실처럼 단정하는 문장
- [ ] 사용자 입력이 모델 지시를 바꾸려는 시도(프롬프트 주입) – 자유 입력을 받는 경우

**운영 장치**
- 모든 생성 결과에 생성 요청 ID, 모델·프롬프트 버전, 검사 결과, 유사도 점수를 저장한다.
- '이상해요' 신고는 즉시 해당 콘텐츠를 비공개 처리하고 검수 대기열로 보낸다.
- 'AI가 만든 이야기' 표시를 화면에 분명히 한다. (부모의 AI 수용도는 설문 Part E와 추가 문항으로 확인)
- Apple 키즈, Google Families 정책에서 생성형 AI 콘텐츠에 대한 요건을 출시 전에 확인한다. (기획서 p.8의 항목에 이미 포함)

## 5. 타입캐스트(Typecast) 낭독

### 5.1 확인된 사양 (웹 검색으로 확인한 공식 문서 요약)

| 항목 | 확인된 내용 |
|---|---|
| 모델·언어 | 최신 모델 ssfm-v30, ssfm-v21 지원. 37개 언어 소개 |
| 감정 제어 | ssfm-v30은 **프리셋**(normal, happy, sad, angry, whisper, toneup, tonedown)과 **스마트 모드**(앞뒤 문맥으로 AI가 감정 추론) 제공. 프리셋은 강도 지정 가능 |
| 속도·음높이·음량 | 템포 0.5~2.0배, 피치 -12~+12 반음, 라우드니스(LUFS) 조절 |
| 오디오 포맷 | WAV, MP3. 문서상 MP3가 필요하면 WAV 생성 후 서버/앱에서 변환하도록 안내 |
| 스트리밍 | 청크 오디오 스트리밍 엔드포인트 제공, 응답 속도 200ms 소개(공급사 주장) |
| 타임스탬프 | 단어·문자 단위 정렬 데이터 제공. 자막·노래방식 하이라이트·립싱크용으로 안내 |
| SDK | Python, JavaScript/TypeScript, PHP, Ruby, C/C++, Dart, Java 등 공식 SDK 안내. 문서에서 **API 키는 백엔드를 거쳐 호출**하도록 권장 |
| SSML | 검색에서는 지원 여부를 확인하지 못함 → 공식 API 레퍼런스에서 확인 필요 |

출처는 문서 끝의 링크를 참고하세요. 요금, 속도 파라미터의 실제 필드명, 화자(보이스) 목록과 어린이 콘텐츠 적합 여부는 확인하지 못했습니다.

**기획서 요구와의 대응**
- 기획서 p.3 "나레이션 + 하이라이트" → 타임스탬프로 문장·단어 하이라이트 구현 가능성이 높음.
- 기획서 p.5 `StoryPage`의 "오디오 타이밍" → 타임스탬프 응답을 저장.
- 기획서 p.6 "나레이션: TTS·문장 타이밍" → 이 기능과 동일한 공정.
- 기획서 p.3 오프라인 저장 → 합성한 오디오를 파일로 저장해 다운로드 제공.

### 5.2 낭독 설계

| 요소 | 설계 (제안값, 실제 청취 테스트로 조정) |
|---|---|
| 화자 | 내레이터 1명 + 주요 등장인물 최대 2명. 월령이 낮을수록 화자를 줄여 혼란 방지 |
| 보이스 선정 | 어린이 대상 콘텐츠에 적합한 차분하고 또렷한 보이스를 청취 테스트로 선정. 보이스 ID와 이용 조건을 기록 |
| 일반 낭독 | 감정 normal 또는 스마트 모드, 템포 1.0 전후 |
| 잠자리 모드 | whisper 또는 낮은 강도 프리셋, 템포를 소폭 낮춤(예: 0.85~0.9), 마지막 문장은 더 느리게 |
| 의성의태어·반복구 | 문장 단위로 따로 합성해 억양을 확인, 필요 시 발음 사전 적용 |
| 고유명사 | 등장인물 이름 발음 사전을 만들어 오독을 방지 |
| 길이 관리 | 문장(또는 문단) 단위로 합성해 이어 붙임. 실패한 문장만 재합성 |

### 5.3 오디오 파이프라인

```
본문 → 문장 분할 → 화자/감정 태깅(LLM) → 타입캐스트 호출(문장 단위)
     → 오디오(WAV) + 타임스탬프 → 후처리(무음 보정, 음량 통일, MP3 변환)
     → 스토리지(R2/S3) 저장 → StoryPage.audio 타이밍 기록 → CDN으로 서빙
```

- **캐시**: 사전 제작 콘텐츠와 생성된 이야기 모두 한 번 합성한 파일을 저장해 재생할 때 재호출하지 않는다 (비용 절감).
- **지연 관리**: 생성 직후 첫 문장부터 스트리밍 재생을 쓸 수 있으나, 오프라인 저장과 하이라이트를 위해서는 완성본 파일을 별도로 만든다.
- **실패 대응**: 합성 실패 시 텍스트 모드로 먼저 보여 주고 오디오는 재시도한다. 서비스 장애 시를 대비해 사전 제작 콘텐츠는 이미 저장된 오디오를 쓴다.
- **보안**: API 키는 서버에만 두고, 앱에서 직접 호출하지 않는다.

### 5.4 계약·정책 확인 필요

검색에서 확인한 것: Typecast API 약관(2026-09-01 시행 표기)상 API 이용 허락은 **제한적·비독점·양도 불가** 성격이며, 약관과 기술 문서를 지키는 범위에서 자기 서비스를 운영하는 용도로 부여됩니다. 사용자 제공 음성으로 만드는 음성 복제는 별도로 정의되어 있습니다.

확인하지 못한 것 (서면 확인 필요)
- [ ] 유료·상업 앱에 탑재해 생성 음성을 **재배포(다운로드·오프라인 저장)** 해도 되는지
- [ ] 어린이 대상 콘텐츠에 대한 제한이나 추가 조건
- [ ] 선택한 보이스(성우)의 이용 범위, 초상권·저작권 조건
- [ ] 월 호출량·동시 호출 제한, 요금 구조(크레딧 단가)
- [ ] 생성된 오디오의 저작권 귀속
- [ ] 서비스 종료·약관 변경 시 이미 저장한 오디오의 계속 사용 가능 여부

## 6. 기술 구성 변경

### 6.1 데이터 모델 추가 (기획서 p.5 Prisma 기준)

현재 14개 엔티티에 아래를 더하는 안이다. 기존 `Content`, `Story`, `StoryPage`, `Favorite`, `Child`는 유지한다.

| 엔티티 | 주요 필드 | 용도 |
|---|---|---|
| `StoryChunk` | contentId, pageNo, text, embedding(vector), tags(JSON), ageMin, ageMax, safetyLevel | RAG 검색 단위 |
| `StoryStyleProfile` | contentId, themes, structure, tone, avgSentenceLen, ending | 동화별 스타일 요약 |
| `GenerationRequest` | userId, childId, selectedContentIds, options(JSON), status, model, promptVersion, createdAt | 생성 요청 기록 |
| `GeneratedStory` | requestId, contentId, outline(JSON), safetyReport(JSON), similarityScore, parentApproved, reportedAt | 생성 결과와 검사 기록 |
| `NarrationAsset` | contentId, voiceId, model, audioUrl, timings(JSON), format | 낭독 파일과 타이밍 |

- `Content.source`에 `GENERATED`를 추가하고, `status`에 검수 대기 상태(예: `PENDING_REVIEW`)를 둔다.
- `PUBLISHED`만 앱에 노출한다는 기존 설계 원칙은 그대로 유지한다.
- 생성된 이야기는 해당 사용자에게만 보이는 **비공개 콘텐츠**로 시작한다.

### 6.2 API 추가 (NestJS)

| 메서드·경로 | 설명 |
|---|---|
| `POST /generations` | 선택한 동화 ID와 조건으로 생성 요청 |
| `GET /generations/:id` | 진행 상태와 결과 조회 |

생성은 오래 걸리므로 작업 큐로 처리하고 상태를 폴링하거나 푸시 알림으로 알린다. 기획서의 Redis를 큐로 활용할 수 있다.

## 7. 단계별 도입안

| 단계 | 내용 | 검수 방식 | 비고 |
|---|---|---|---|
| 1단계 (MVP) | 아이가 고른 동화 기반 **취향 추천**(검색만, 생성 없음). 타입캐스트 낭독은 사전 제작 콘텐츠에 적용 | 기존과 동일(전량 검수) | 8주 수정안(07)에 취향 추천(검색 기반)으로 포함, 생성은 내부 PoC만 |
| 2단계 | 요청형 생성: 선택 → 생성 → 사람 검수 → 알림 | 검수 대기열 | 운영 인력과 검수 도구 필요 |
| 3단계 | 즉시 생성(자동 검사 + 부모 승인), 삽화 즉석 생성 검토 | 자동 + 사후 샘플 검수 | 사고 위험이 가장 커서 충분한 데이터 확보 후 판단 |

1단계에서 쌓이는 **선택 이력과 취향 태그**가 2단계 이후 품질의 기반이 된다.

## 8. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 저작권 침해 소지(시판 동화를 코퍼스에 사용) | 법적 분쟁, 스토어 심사 문제 | 코퍼스를 권리가 확인된 작품으로 한정, 외부 책 입력 차단, 유사도 검사 |
| 부적절한 생성 결과 | 부모 신뢰 하락(기획서 p.8 "한 장면만 잘못 나가도 신뢰가 크게 깎인다") | 단계별 검수 방식 선택, 자동 검사, 신고 즉시 비공개 |
| 원문과 지나치게 유사한 결과 | 저작권, 품질 | 연속 문장 일치 검사, 재작성 |
| 생성·TTS 비용 증가 | 무료 모델 유지 어려움 | 생성 횟수 제한, 캐시, 사전 생성 템플릿 활용 |
| 대기 시간 | 이탈 | 진행 표시, 알림, 대기 중 다른 콘텐츠 재생 |
| TTS 약관 제한 | 오프라인 저장·재배포 불가 가능성 | 계약 전 서면 확인(5.4), 대체 TTS 후보 확보 |
| 발음·억양 오류 | 품질 저하 | 발음 사전, 문장 단위 재합성, 청취 테스트 |
| 아이 개인정보 | 개인정보 이슈 | 별칭·생년월만, 이름 삽입 기능은 보류 |
| 사용자 입력을 통한 악용 | 부적절 콘텐츠 | 1~2단계는 선택형 입력만 허용 |

## 10. 결정이 필요한 사항

1. 생성 기능을 MVP에 넣을지, 1단계(취향 추천)만 넣을지
2. 검수 방식 ①②③ 중 선택 (기획서의 '전량 사람 검수' 원칙 유지 여부)
3. 코퍼스에 넣을 퍼블릭 도메인 작품 선정과 번역본 권리 확인 방식
4. 삽화 방식 (A 조합 / B 즉석 생성 / C 오디오 전용)
5. 타입캐스트 계약 조건 확인과 대체 TTS 후보 확보
6. 생성 횟수 제한과 수익 모델의 관계 (무료 유지 vs 일부 유료)
7. 아이 이름을 이야기에 넣는 기능 허용 여부 (개인정보 원칙과 충돌 가능)

## 11. 참고: 멘토링 자료 '주제2'의 나머지 내용

이번 요청 범위(RAG 제안, 타입캐스트)가 아닌 항목은 기획서에 반영하지 않고 기록만 남긴다.

**서비스 아이디어**
- AI 기반 육아 콘텐츠 통합 제공(이유식 정보, 동요, 구연동화), 부적절 콘텐츠 선별·제외, 콘텐츠 제작·검수 파이프라인 구축 → 현재 기획서와 일치
