## 1. 서비스 한 줄 정의와 차별점

**한 줄 정의 (가제)**
> 먹이고, 놀고, 재우는 하루를 한 앱에서 이어 주는, 광고 없는 안심 육아 앱

### 1.1 시장의 빈틈 (조사 근거와 한계)

| 조사에서 확인된 것 | 시사점 |
|---|---|
| 동화·동요 앱은 캐릭터 IP와 영상 중심이다(핑크퐁 등). 유튜브 키즈는 타이머와 보호자 설정이 있다 | 콘텐츠 안전과 시간 관리는 이미 기본 기능이다. 단독 차별점이 되기 어렵다 |
| 코코지는 여러 캐릭터의 동요·동화 오디오를 한 앱에 모은다 | 통합 자체는 선례가 있다 |
| 베이비타임 등 기록 앱은 이유식 기록을 제공하지만 콘텐츠가 없다 | 기록과 콘텐츠의 연결이 비어 있을 수 있다 |
| 이유식과 콘텐츠를 **상황별로 묶어 하루 흐름으로 제공**하는 앱은 이번 조사 범위에서 확인하지 못했다 | 빈틈일 가능성이 있다. 다만 검색 범위가 좁아 "없다"고 단정할 수 없고, 인터뷰·설문으로 검증한다 |

"광고 없는 무료"와 "AI 제작"만으로는 부모가 갈아탈 이유가 약하다. 아래 차별점은 이 약점을 메우기 위해 새로 만들었다.

### 1.2 차별점 4가지

| 구분 | 이름 | 한 줄 설명 | 부모에게 주는 가치 |
|---|---|---|---|
| A | **하루 루틴 팩** | 상황(먹는 시간·놀이·잠자리·외출)을 고르면 월령에 맞는 동요·동화·이유식을 한 묶음으로 이어서 재생 | 고르는 수고를 없애고, 육아 상황에 바로 쓸 수 있다 |
| B | **재료 이야기 연결** | 새 재료 도전을 기록하면 그 재료가 나오는 동화·동요가 연결되고, 먹이기 전에 이야기를 먼저 들려줄 수 있다 | 편식·거부 시기의 부담을 덜고, 기록이 놀이로 이어진다 |
| C | **제작·검수 투명 배지** | 모든 콘텐츠에 제작 방식(AI 보조/사람 제작), 검수 완료일, 원작 출처·라이선스를 표시 | AI 콘텐츠에 대한 불안을 정면으로 해소한다 |
| D | **캐릭터 6종의 하루 동행** | 곰(잠자리), 수달(이유식), 고래(동요), 다람쥐(동화), 고슴도치(새 재료), 공룡(율동)이 상황별 안내자로 등장 | 아이가 친구처럼 느끼고 앱을 찾게 된다. IP로 확장 가능하다 |

### 1.3 차별점 상세

**A. 하루 루틴 팩**

| 항목 | 내용 |
|---|---|
| 화면 | 홈 상단에 상황 버튼 4개(먹는 시간, 놀이 시간, 잠자리 시간, 외출). 누르면 아이 월령에 맞는 묶음이 큐로 재생된다 |
| 예시 | **잠자리 팩**: 조용한 동요 1곡 → 짧은 동화 1편(낭독) → 자장가 반복 → 설정한 타이머(15·30·45분)에 맞춰 볼륨이 서서히 줄며 정지. **먹는 시간 팩**: 식사 동요 → 오늘 도입 재료 이야기. **외출 팩**: 오프라인 저장된 동요·동화 오디오 |
| 구현 | AI 없이 **규칙 기반**. 콘텐츠에 상황 태그와 길이(초) 필드를 두고, 월령·상황·남은 시간으로 조건 검색해 큐를 만든다 |
| 8주 안의 범위 | 팩 4종은 고정 규칙으로 구성한다. 사용자 맞춤 편집은 2차 |
| 측정 | 루틴 팩 사용 비율, 잠자리 팩 끝까지 재생한 비율 |
| 검증 | 인터뷰: 상황별로 어떻게 콘텐츠를 쓰는지(Q7), 설문: 팩 관심도(아래 10장 문항) |

**B. 재료 이야기 연결**

| 항목 | 내용 |
|---|---|
| 흐름 | 이유식 상세에서 '새 재료 도전' → 해당 재료 이야기(동화 또는 동요) 듣기 → "처음 먹여봤어요" 기록(날짜·재료·반응) → 보관함 달력에 누적, 도전 스티커(고슴도치) |
| 구현 | 재료와 콘텐츠를 다대다로 연결한다(`Ingredient`–`Content`). 재료 테마 동화 5편, 동요 3곡을 제작해 연결한다 |
| 주의 | 반응 기록은 의료 판단이 아니다. 기획서의 "아이 상태에 따라 소아과와 상담하세요" 문구를 이유식 화면 상단에 항상 표시한다 |
| 측정 | 새 재료 기록 후 연결 콘텐츠 재생률 |

**C. 제작·검수 투명 배지**

| 항목 | 내용 |
|---|---|
| 화면 | 콘텐츠 상세에서 배지를 누르면 시트가 열린다: 제작 방식, 검수 완료일, 원작과 라이선스, 이유식은 참고한 공공 가이드 출처 |
| 설정 화면 | '안심 약속' 페이지: 광고 없음, 외부 링크 없음, 아이 정보는 별칭·생년월만, 모든 콘텐츠는 사람이 검수 |
| 구현 | `Content`에 제작 방식, 검수 완료일, 출처·라이선스 필드를 추가하고 상세 화면에 표시한다. 기획서 p.8의 체크리스트와 같은 정보다 |
| 이유 | 부모의 AI 수용도는 시장조사의 핵심 가설이다. 조건부 수용층에게는 투명성이 구매 이유가 된다 |
| 측정 | 배지 열람률, 설문의 AI 안심 조건(E4) |

**D. 캐릭터 6종의 하루 동행**

| 캐릭터 | 화면에서 맡는 일 |
|---|---|
| 아기 반달가슴곰 | 잠자리 모드. 타이머가 끝나면 곰이 잠드는 연출 |
| 아기 수달 | 이유식 탭 안내 |
| 아기 고래 | 동요 탭, 재생 화면 |
| 다람쥐 | 동화 탭, 낭독 안내자 |
| 아기 고슴도치 | 새 재료 기록 버튼, 도전 스티커 |
| 아기 공룡 | 율동 영상(루프 3곡) |

홈은 6종이 함께 나오는 화면으로 구성한다. 8주 안에서는 캐릭터를 정지 이미지와 간단한 표정 교체로 쓰고, 파츠 애니메이션은 곰·고래·공룡 3종에 한정한다.

### 1.4 2차에 여는 차별점 (확장 로드맵)

| 기능 | 내용 | 재진입 조건 |
|---|---|---|
| 맞춤 동화 생성(RAG) | 좋아하는 동화를 고르면 새 이야기를 생성하고 타입캐스트로 낭독 | 검수 방식 결정, 저작권·TTS 약관 확인, 시장조사 H6~H8 결과 |
| 울음 감지 | 울음 감지 알림(참고용) | 규제 검토, 평가 데이터 확보 |
| 성장 기록 | 기획서의 2차 기능 | MVP 사용 데이터 확인 |

A~D가 쌓은 **상황 태그와 재료 연결 데이터**가 2차 기능의 기반이 된다.

## 2. 수정 범위: 원안과 8주안 비교

| 항목 | 원안(10주) | 8주안 | 이유 |
|---|---|---|---|
| 동화 | 20편(재창작 10 + 오리지널 10) | **10편**(재료 테마 5 포함) | 편당 제작 시간이 가장 큼 |
| 동요 | 20곡 | **10곡**(재료·식사 테마 3 포함, 율동 루프 3) | 영상은 2D 루프만 |
| 이유식 레시피 | 40개 | **20개**(초기·중기·후기·완료기 각 5) | 단계 구조는 유지 |
| 동요 영상 | 2D·3D 혼합 | **2D 루프만**, 나머지는 오디오 + 정지 이미지 | 3D 파이프라인(Meshy, Blender)은 2차 |
| 나레이션 | 타입캐스트 TTS + 문장 타이밍 | 동화 10편을 **사전 합성**, 하이라이트는 **문장 단위** | 단어 단위는 2차 |
| 오프라인 저장 | 공통 기능 | **오디오만** | 영상·HLS 제외 |
| 로그인 | 카카오·Apple·Google | **비로그인 사용 + 카카오·Apple** 로그인 | 구글은 2차. Apple 로그인은 iOS 정책 확인 |
| 서버 | NestJS + Postgres + Redis + R2/S3 | **Supabase(Postgres, 인증, 스토리지) 후보** + CDN | 서버 개발 시간 절감 |
| 관리자 | Next.js 관리자 앱 | **최소 관리 화면**(목록, 상태 변경, 배지 필드) 또는 Supabase 관리 화면 + 검수 체크리스트 | 콘텐츠 입력은 스크립트 일괄 등록 |
| 성장 기록·커뮤니티·다국어·구독 | 2차 | 2차 유지 | |
| 맞춤 동화 생성(RAG), 울음 감지, 제휴 상품 추천, 돌봄 연계 | (기획서 외) | 2차 이후 | 별도 검토 중 |

**유지하는 핵심**: 하단 탭 5개, 미니 플레이어, 아이 프로필(월령), 즐겨찾기, 잠자리 타이머, 새 재료 기록, 모든 콘텐츠 사람 검수 후 공개(PUBLISHED만 노출).

## 4. 콘텐츠 제작 계획

### 4.1 수량과 시간 예산 (가정값)

| 종류 | 수량 | 편당 목표 시간 | 합계 |
|---|---|---|---|
| 동화 | 10편 | 약 4시간 | 약 40시간 |
| 동요 | 10곡 | 약 3시간 | 약 30시간 |
| 이유식 레시피 | 20개 | 약 1시간 | 약 20시간 |
| 검수·보정 | 전체 | | 약 20시간 |
| **합계** | 40개 | | **약 110시간** |

- 시간 목표는 근거 있는 값이 아니다. 1주차 시범 제작 결과로 조정한다. 결과가 목표의 1.5배를 넘으면 수량을 먼저 줄이고, 줄일 순서는 이유식 → 동요 → 동화로 한다.
- 개발에 약 200시간, 콘텐츠에 약 110시간, 계약·QA·제출에 약 40시간을 잡으면 합계 약 350시간으로, 주 40~45시간 1인 기준 8주에 빠듯하다. **1인으로는 여유가 거의 없다**는 점을 전제로 일정을 짜야 한다.

### 4.2 제작 방식 (간소화)

| 종류 | 공정 | 8주안의 변경 |
|---|---|---|
| 동화 | 원고(LLM) → 캐릭터 시트 고정 → 장면 일러스트 → 타입캐스트 낭독·문장 타이밍 → 사람 검수 | 캐릭터 6종 중 필요한 종만 사용. 장면은 5~8컷으로 제한. 낭독은 사전 합성 |
| 동요 | 가사·음원 → 2D 루프(필요한 3곡) → 사람 검수 | 음원은 **전래 동요 편곡 중심**으로 제한(결정 필요). AI 음악 서비스를 쓰려면 상업 라이선스 확인이 먼저 |
| 이유식 | 레시피 원고 → 공공 영양 가이드 대조 → 사진·일러스트 → 사람 검수 | 레시피 이미지는 재료 일러스트 위주 |

차별점 연계 콘텐츠: 재료 테마 동화 5편, 동요 3곡을 처음부터 기획해서 만든다. 상황 태그(먹는 시간·놀이·잠자리·외출)와 길이(초)를 제작 시점에 입력한다.

## 5. 기술 구성 (간소화안)

| 구분 | 원안 | 8주안 |
|---|---|---|
| 앱 | Expo (React Native) | 유지. 백그라운드 오디오는 개발 빌드가 필요할 수 있어 **1~3주차에 먼저 검증** |
| 서버 | NestJS + Prisma + Postgres + Redis | **Supabase(Postgres, 인증, 스토리지)** 후보. 인증의 카카오·Apple 지원 여부는 공식 문서에서 확인 필요 |
| 미디어 | R2/S3 + CDN + HLS | 스토리지 + CDN, **MP3·이미지·짧은 mp4**. HLS 제외 |
| 캐시 | Redis | 제외 |
| 관리자 | Next.js | 최소 관리 화면 또는 일괄 등록 스크립트 + 관리 도구 |
| 낭독 | 타입캐스트 | 동화 10편 사전 합성. 오프라인 저장·재배포 허용 여부는 약관 확인 필요, 불허면 스트리밍 전용 또는 대체 TTS |

**데이터 모델 추가 필드** (기획서 p.5의 14개 엔티티 기준)
- `Content`: `situation`(상황 태그 배열), `durationSec`, `productionMethod`, `reviewedAt`, `sourceLicense`
- `Ingredient`–`Content` 다대다 연결
- 루틴 팩은 별도 테이블 없이 규칙 조회로 구성한다.

## 9. 결정이 필요한 사항 (1주차 안에)

1. 앱 이름과 '바른말이' 사용 여부
2. 인원 가정(1인/2인 이상)
3. 동요 음원 방식(전래 편곡 / AI 음악 / 외주)
4. 타입캐스트 오프라인 저장 허용 여부, 불허 시 대안
5. 서버 방식(Supabase 등 관리형 / 기존 NestJS)
6. 로그인 범위(비로그인 + 카카오·Apple)
7. 차별점 A~D의 8주 범위 확정(특히 루틴 팩 4종과 재료 연결 5종)
8. 수익 모델(완전 무료 유지 여부)
