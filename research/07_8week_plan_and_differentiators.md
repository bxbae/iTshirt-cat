## 1. 서비스 한 줄 정의와 차별점

**한 줄 정의 (가제)**
> 먹이고, 놀고, 재우는 하루를 한 앱에서 이어 주는, 광고 없는 안심 육아 앱

### 1.1 시장의 빈틈 (조사 근거와 한계)

| 조사에서 확인된 것 | 시사점 |
|---|---|
| 동화·동요 앱은 캐릭터 IP와 영상 중심이다(핑크퐁 등). 유튜브 키즈는 타이머와 보호자 설정이 있다 | 콘텐츠 안전과 시간 관리는 이미 기본 기능이다. 단독 차별점이 되기 어렵다 |
| 코코지는 여러 캐릭터의 동요·동화 오디오를 한 앱에 모은다 | 통합 자체는 선례가 있다 |
| 베이비타임 등 기록 앱은 이유식 기록을 제공하지만 콘텐츠가 없다 | 기록과 콘텐츠의 연결이 비어 있을 수 있다 |
| 이유식과 콘텐츠를 **상황별로 묶어 하루 흐름으로 제공**하는 앱은 이번 조사 범위에서 확인하지 못했다 | 빈틈일 가능성이 있다. 검색 범위가 좁아 "없다"고 단정할 수 없고, 인터뷰·설문으로 검증한다 |

"광고 없는 무료"와 "AI 제작"만으로는 부모가 갈아탈 이유가 약하다. 아래 차별점은 이 약점을 메우기 위해 새로 만들었다.

### 1.2 차별점 5가지

| 구분 | 이름 | 한 줄 설명 | 부모에게 주는 가치 |
|---|---|---|---|
| A | **하루 루틴 팩** | 상황(먹는 시간·놀이·잠자리·외출)을 고르면 월령에 맞는 동요·동화·이유식을 한 묶음으로 이어서 재생 | 고르는 수고를 없애고 육아 상황에 바로 쓴다 |
| B | **재료 이야기 연결** | 새 재료 도전을 기록하면 그 재료가 나오는 동화·동요가 연결되고, 먹이기 전에 이야기를 먼저 들려줄 수 있다 | 편식·거부 시기의 부담을 덜고, 기록이 놀이로 이어진다 |
| C | **제작·검수 투명 배지** | 모든 콘텐츠에 제작 방식(AI 보조/사람 제작), 검수 완료일, 원작 출처·라이선스를 표시 | AI 콘텐츠에 대한 불안을 정면으로 해소한다 |
| D | **캐릭터 6종의 하루 동행** | 곰(잠자리), 수달(이유식), 고래(동요), 다람쥐(동화), 고슴도치(새 재료), 공룡(율동)이 상황별 안내자로 등장 | 아이가 친구처럼 느끼고 앱을 찾는다. IP로 확장 가능하다 |
| E | **우리 아이 취향 이야기** | 아이가 좋아하는 동화(즐겨찾기·끝까지 들은 횟수)를 바탕으로 비슷한 분위기의 동화를 추천 | 새 콘텐츠를 찾는 수고를 줄이고, 2차의 맞춤 동화 생성으로 이어진다 |

### 1.3 차별점 상세

**A. 하루 루틴 팩**

| 항목 | 내용 |
|---|---|
| 화면 | 홈 상단에 상황 버튼 4개(먹는 시간, 놀이 시간, 잠자리 시간, 외출). 누르면 아이 월령에 맞는 묶음이 큐로 재생된다 |
| 예시 | **잠자리 팩**: 조용한 동요 1곡 → 짧은 동화 1편(낭독) → 자장가 반복 → 타이머(15·30·45분)에 맞춰 볼륨이 줄며 정지. **먹는 시간 팩**: 식사 동요 → 오늘 도입 재료 이야기. **놀이 팩**: 율동 동요 → 율동 영상. **외출 팩**: 오프라인 저장된 동요·동화 |
| 구현 | AI 없이 **규칙 기반**. 콘텐츠에 상황 태그와 길이(초)를 두고, 월령·상황·남은 시간으로 큐를 만든다 |
| 6인안 추가 | 팩 4종 기본 제공 + 부모가 곡·동화를 골라 '나만의 루틴'을 저장(여유 시) |
| 측정 | 루틴 팩 사용 비율, 잠자리 팩 끝까지 재생한 비율 |

**B. 재료 이야기 연결**

| 항목 | 내용 |
|---|---|
| 흐름 | 이유식 상세에서 '새 재료 도전' → 재료 이야기(동화 또는 동요) 듣기 → "처음 먹여봤어요" 기록(날짜·재료·반응) → 보관함 달력에 누적, 도전 스티커(고슴도치) |
| 구현 | 재료와 콘텐츠를 다대다로 연결(`Ingredient`–`Content`). 재료 테마 동화 **10편**, 동요 **5곡**을 만들어 연결 |
| 주의 | 반응 기록은 의료 판단이 아니다. 이유식 화면 상단에 "아이 상태에 따라 소아과와 상담하세요"를 항상 표시한다(기획서 p.4) |
| 측정 | 새 재료 기록 후 연결 콘텐츠 재생률 |

**C. 제작·검수 투명 배지**

| 항목 | 내용 |
|---|---|
| 화면 | 콘텐츠 상세에서 배지를 누르면 시트가 열린다: 제작 방식, 검수 완료일, 원작과 라이선스, 이유식은 참고한 공공 가이드 출처 |
| 설정 화면 | '안심 약속' 페이지: 광고 없음, 외부 링크 없음, 아이 정보는 별칭·생년월만, 모든 콘텐츠는 사람이 검수 |
| 구현 | `Content`에 제작 방식, 검수 완료일, 출처·라이선스를 추가해 상세 화면에 표시. 기획서 p.8 체크리스트와 같은 정보다 |
| 측정 | 배지 열람률, 설문의 AI 안심 조건(E4) |

**D. 캐릭터 6종의 하루 동행**

| 캐릭터 | 화면에서 맡는 일 |
|---|---|
| 아기 반달가슴곰 | 잠자리 모드. 타이머가 끝나면 곰이 잠드는 연출(파츠 애니메이션) |
| 아기 수달 | 이유식 탭 안내 |
| 아기 고래 | 동요 탭, 재생 화면(파츠 애니메이션) |
| 다람쥐 | 동화 탭, 낭독 안내자 |
| 아기 고슴도치 | 새 재료 기록 버튼, 도전 스티커 |
| 아기 공룡 | 율동 영상(파츠 애니메이션) |

홈은 6종이 함께 나오는 화면으로 구성한다. 6종 모두 표정 세트를 만들고, 파츠 애니메이션은 곰·고래·공룡 3종부터 시작한다.

**E. 우리 아이 취향 이야기 (RAG 1단계)**

| 항목 | 내용 |
|---|---|
| 흐름 | 즐겨찾기·재생 완주 이력 → 취향 태그 요약 → 홈과 동화 탭의 '비슷한 이야기' 추천 |
| 구현 | 1차는 태그·메타데이터 유사도로 구현한다. 임베딩 검색(pgvector)은 시간이 남으면 적용 |
| 저장 정보 | 콘텐츠 ID와 태그만 저장한다. 부모가 초기화할 수 있다 |
| **생성 PoC (앱 미노출)** | 6~8주차에 내부 PoC를 병행한다: 선택 동화 3편 → 생성 → 자동 안전 검사 → 타입캐스트 낭독 → 사람 검수. 결과는 2차 공개 여부를 판단하는 자료로 쓴다(`04_맞춤동화_RAG_제안` 참조) |

## 3. 팀 구성과 역할 (제안)

6명의 이름을 역할에 배정하는 일은 팀에서 정한다. 아래는 필요한 역할이다. 한 사람이 둘 이상을 겸해도 되지만, **각 역할의 책임자는 한 명**으로 정한다.

| 역할 | 주 업무 | 예상 시간(가정) |
|---|---|---|
| R1 PM·QA·이유식 원고 | 일정·결정 관리, 인터뷰·설문, 약관·정책 확인, 테스트 계획·실행, 스토어 제출, 이유식 레시피 원고와 공공 가이드 대조 | 약 230시간 |
| R2 앱 A (재생) | 오디오·영상 플레이어, 미니 플레이어, 백그라운드 재생, 오프라인 저장, 잠자리 모드, 루틴 팩 | 약 200시간 |
| R3 앱 B (화면) | 홈, 동화 뷰어(그림책·하이라이트), 이유식, 새 재료 기록·달력, 보관함, 로그인, 배지·캐릭터 연출 | 약 200시간 |
| R4 플랫폼 | DB 스키마, API, 인증, 스토리지·CDN, 관리자, 배포·CI, 취향 추천, 생성 PoC | 약 230시간 |
| R5 콘텐츠 | 동화 원고·장면 일러스트, 타입캐스트 낭독·타이밍, 재료 테마 콘텐츠, 콘텐츠 일괄 등록 | 약 200시간 |
| R6 디자인·동요 | UI 디자인 시스템, 캐릭터 자산(표정·파츠), 동요 음원·가사·율동 루프, 스토어 그래픽 | 약 220시간 |
| **합계** | | **약 1,280시간** |

6명이 주 30시간씩 8주를 쓰면 약 1,440시간이다. 위 계획은 **약 89%** 수준으로, 나머지는 버퍼다. 가용 시간이 이보다 적으면 2장의 수량부터 줄인다.

**검수 책임**: 콘텐츠 최종 승인자는 R1과 팀장이 함께 맡는다(기획서 p.6의 "사람 검수를 거쳐야 공개"). 콘텐츠 제작자와 검수자를 분리한다.

## 5. 콘텐츠 제작 계획

### 5.1 수량과 시간 예산 (가정값)

| 종류 | 수량 | 편당 목표 | 합계 | 담당 |
|---|---|---|---|---|
| 동화 | 20편 | 약 4시간 | 약 80시간 | R5 |
| 동요 | 20곡 | 약 3시간 (루프 6곡은 추가) | 약 70시간 | R6 |
| 이유식 | 40개 | 약 1시간 | 약 40시간 | R1 |
| 검수·보정 | 전체 | | 약 40시간 | R1·팀장 |
| **합계** | 80개 | | **약 230시간** | |

주당 제작 속도는 동화 4편, 동요 4곡, 이유식 8개다. 1주차 시범 제작 결과가 목표의 1.5배를 넘으면 이유식 → 동요 → 동화 순으로 수량을 줄이는 쪽을 먼저 검토한다.

### 5.2 제작 방식

| 종류 | 공정 | 비고 |
|---|---|---|
| 동화 | 원고(LLM) → 캐릭터 시트 고정(ComfyUI) → 장면 일러스트(이미지 편집 모델) → 타입캐스트 낭독·문장 타이밍 → 사람 검수 | 기획서 p.6 파이프라인 |
| 동요 | 가사·음원 → 2D 파츠 루프(율동 6곡) → 사람 검수 | 음원은 **전래 동요 편곡**을 우선하고, AI 음악 서비스는 상업 라이선스 확인 후 결정 |
| 이유식 | 레시피 원고 → 공공 영양 가이드 대조 → 사진·일러스트 → 사람 검수 | 면책 문구 포함 |

차별점 연계: 재료 테마 동화 10편, 동요 5곡을 처음부터 기획해 만들고, 모든 콘텐츠에 상황 태그와 길이(초)를 제작 시점에 입력한다.

## 6. 기술 구성

| 구분 | 선택 | 비고 |
|---|---|---|
| 앱 | Expo (React Native) | 백그라운드 오디오는 개발 빌드가 필요할 수 있어 **1~3주차에 실기기로 먼저 검증** |
| 서버 | **A안**: 원안 NestJS + Prisma + Postgres / **B안**: Supabase(Postgres·인증·스토리지) | 아래 비교 참조 |
| 캐시 | Redis는 **제외**(필요해질 때 추가) | 홈 추천은 DB 쿼리로 시작 |
| 미디어 | 스토리지(R2 또는 S3) + CDN, MP3·이미지·mp4 | HLS는 2차 |
| 관리자 | Next.js | 콘텐츠 등록·검수·공개 |
| 낭독 | 타입캐스트(동화 20편 사전 합성) | 오프라인 저장·재배포 허용은 약관 확인 필요, 불허면 스트리밍 전용이나 대체 TTS |
| 협업 | GitHub, PR 리뷰 1명 이상, GitHub Actions(린트·테스트·빌드), EAS Build, 환경 3개(개발·스테이징·운영) | |

**서버 방식 비교**

| 항목 | A안 NestJS + Postgres | B안 Supabase |
|---|---|---|
| 개발 시간 | 인증·API·관리자 API를 직접 구현 | 인증과 기본 API를 제공해 짧음 |
| 유연성 | 높음. 추천·큐·생성 PoC에 유리 | 기본 기능 밖은 별도 구성 필요 |
| 운영 부담 | 서버 운영 필요 | 관리형이라 낮음 |
| 팀 적합성 | R4가 NestJS 경험이 있을 때 | R4의 일정 여유가 부족할 때 |

멘토링 메모에는 "처음에 서버를 직접 구축하고 Supabase로 이관(비용 절감)"하는 아이디어가 적혀 있다. 이 방식을 쓸지 여부도 함께 결정한다. 현재는 **R4의 경험에 맞춰 선택**하길 권장한다. Supabase의 카카오·Apple 로그인 지원은 공식 문서로 확인하지 못했다.

**데이터 모델 추가 필드** (기획서 p.5의 14개 엔티티 기준)
- `Content`: `situation`(상황 태그 배열), `durationSec`, `productionMethod`, `reviewedAt`, `sourceLicense`
- `Ingredient`–`Content` 다대다 연결
- 취향 추천용 `ContentTag` 또는 태그 배열, 재생 완주 이력(`PlayHistory`)
- 루틴 팩은 규칙 조회로 구성한다(별도 테이블 불필요).

## 9. 인원이 줄거나 일정이 밀릴 때 줄이는 순서

1. 단어 단위 하이라이트, '나만의 루틴' 저장
2. 취향 추천의 임베딩 검색(태그 방식 유지)
3. 영상 오프라인 저장(오디오만 유지)
4. 율동 루프 영상 6곡 → 3곡
5. 콘텐츠 수량: 이유식 40 → 28, 동요 20 → 14, 동화 20 → 14
6. 구글 로그인
7. 생성 PoC (중단)

**줄이지 않는 것**: 잠자리 모드, 새 재료 기록, 루틴 팩(A), 제작·검수 배지(C), 사람 검수 후 공개.

## 10. 결정이 필요한 사항 (1주차 안에)

1. **6명의 역할 배정과 주당 가용 시간**
2. 앱 이름과 '바른말이' 사용 여부
3. 서버 방식(A안 NestJS / B안 Supabase), 멘토링 메모의 이관 방식 채택 여부
4. 동요 음원 방식(전래 편곡 / AI 음악 / 외주)
5. 타입캐스트 오프라인 저장 허용 여부와 불허 시 대안
6. 차별점 A~E의 8주 범위 확정(루틴 팩 4종, 재료 연결 10종, 취향 추천 방식)

8. 수익 모델(완전 무료 유지 여부)
9. 개발자 계정 등록 담당자
